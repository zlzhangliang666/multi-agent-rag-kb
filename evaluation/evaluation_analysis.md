# 评测结果分析与改进建议

> 分析对象：`evaluation/evaluation_summary.md` 所汇总的 6 组配置、2 种生成后端、36 条查询的评测数据
> 分析日期：2026-10-28　|　系统版本：多 Agent 协同 RAG（Vue3 + FastAPI + Chroma + BM25 + LangGraph + Qwen2.5-1.5B / DeepSeek）

---

## 0. 摘要

1. **检索层已接近饱和**：精排开启后 Hit@4 = 97.2%、MRR = 0.9537；唯一 MISS 是文档本身只有 3 行外链的 how-04，属语料缺陷而非检索缺陷。
2. **精排是确定性净收益**：MRR 0.8843 → 0.9537（检索过程无采样随机性，该差值可信），代价是单 query +1.6s。
3. **引用正确率没有实质变化**：本地 89.3% → 外部 90.4%，两者 95% 置信区间（约 ±8pt）完全重叠，差异落在噪声内。
4. **答案完整度确有提升**：外部模型答案覆盖 87.0% → 94.4%（+7.4pt），回答长度中位数 505 → 1030 字；但按 36 条样本的置信区间仍属「倾向性证据」而非「确证」。
5. **外部 judge 分数不可横向比较**：58.7% 是 DeepSeek 评本地答案，87.8% 是 DeepSeek 评自己，后者存在系统性自评偏高（约 +29pt），不能作为质量跃升的证据。
6. **最大瓶颈已从检索转移到语料**：语料把代码示例写成 `{* docs_src/... *}` 占位符，任何补写代码的句子都无法被判为「有资料支撑」，这是外部 judge 偏低的主因，也是当前唯一值得优先投入的方向。

## 1. 评测设计回顾

### 1.1 实验条件

| 项 | 取值 |
|---|---|
| 知识库 | FastAPI 中文文档 123 篇 / 1777 chunks |
| 检索 | bge-small-zh-v1.5（ONNX）+ Chroma + BM25（jieba）+ RRF(k=60) + bge-reranker-base（ONNX 量化） |
| 生成 A（默认） | Qwen2.5-1.5B-Instruct GGUF Q4_K_M，纯 CPU，temperature 0.7 |
| 生成 B（对照） | deepseek-chat，temperature 0.7 |
| 检索参数 | top_k=5，min_score_ratio=0.5，min_sources=2；精排 max_candidates=12 / max_length=256 / batch=8 |
| 评测集 | 36 条（入门 22 / 进阶 7 / 部署 3 / 操作指南 4），每题带 keywords / answer_keywords |
| 运行环境 | Windows，16 逻辑核 / 8 物理核，31.9 GB，纯 CPU 推理 |

### 1.2 指标定义与计算方式

| 指标 | 计算方式 | 性质 |
|---|---|---|
| Hit@4 | Top-4 中任一来源的 doc_name/section/正文包含任一 keyword | 检索，二值 |
| MRR | 首个命中来源排名的倒数，未命中记 0 | 检索，连续 |
| 引用正确率 | 每题「命中来源数 / 引用来源数」的算术平均 | 关键词启发式 |
| 引用覆盖率 | 至少 1 条相关引用的题目占比 | 关键词启发式 |
| 词面忠实度 | 按 `。！？；\n` 切句（≥8 字），句内内容词 ≥60% 出现在**整个上下文词集合**中即判为被支撑 | 词面启发式 |
| LLM judge | 逐句判断「是否被资料直接支持（语义等价即可）」，报 supported/total | 语义判定 |
| 答案覆盖度 | 回答中出现的 answer_keywords 占该题关键词总数的比例 | 关键词命中 |
| TTFT / 总耗时 | SSE 首帧时间 / 请求到结束的总时间 | 性能 |

**关键实现细节**（影响后文解读）：

- 词面忠实度用「全部上下文词集合」做并集匹配，上下文越长越容易被判为支撑，且不校验语序、数值与代码块归属。
- 引用正确率是「任一关键词命中」即算相关，属于**宽松**判定；但遇到 how-04 这种复合词（「测试数据库」被拆成测试/数据库）又变得**脆弱**。
- judge 的 context 截断到 3000 字符、answer 截断到 2500 字符，Top-5 上下文可能超出，被截断部分的正确句子会被误判为无支撑。

## 2. 总体结果

| 维度 | 本地 Qwen2.5-1.5B | 外部 deepseek-chat |
|---|---|---|
| 检索 Hit@4 / MRR | 97.2% / 0.9537（同一检索，共用） | 同左 |
| 引用正确率 | 89.3% | 90.4% |
| 引用覆盖率 | 97.2% | 97.2% |
| 词面忠实度 | 78.8% | 78.0% |
| LLM judge | 58.7%（DeepSeek 评） | 87.8%（DeepSeek 自评） |
| 答案覆盖度 | 87.0% | 94.4% |
| 平均总耗时 | 23.9s | 5.0s |
| 失败数 | 0/36 | 0/36 |

一句话结论：**检索质量决定了引用指标的上限，生成模型决定答案的完整度与速度；当前检索已接近语料允许的上限，剩余提升空间在语料与生成约束上。**

## 3. 检索层分析

### 3.1 精排的效果是真实且可解释的

| 指标 | 精排前 | 精排后 | 变化 |
|---|---|---|---|
| Hit@4 | 100.0% | 97.2% | −2.8pt |
| MRR | 0.8843 | 0.9537 | +0.0694 |
| 延迟 | 191.7 ms | 1759.2 ms | +1567.5 ms |

- **Hit@4 下降 1 条不等于变差**：Hit@4 是「Top-4 有没有」的二值指标，MRR 反映「第一条对的多靠前」。MRR 提升 0.069 说明大量题目的首个相关来源从第 2~3 位前移到第 1 位，这对生成端的上下文噪声更敏感、收益更直接。
- **唯一 MISS 是 how-04**：目标是 `testing-database.md`，该文件在语料中只有 3 行外链占位（无正文），而 `testing-dependencies.md` / `testing-settings.md` 内容更丰富且与关键词高度重叠。这是「语料无内容」问题，不是排序问题，用标题硬提权会误伤其他 17/36 条，不建议改。
- **延迟代价明确**：精排从 1.6s 量级（max_candidates=12、max_length=256）占据了检索总耗时的 90%+，这是当前端到端延迟的主要来源；但相对 12~24s 的生成耗时仍属次要项。

### 3.2 检索层的剩余问题不是「召回」而是「纯度」

| 题目 | 引用正确率 | 命中/引用 | 说明 |
|---|---|---|---|
| dep-01 | 20%（外部 33%） | 1/5（外部 1/3） | 命中了 Docker 相关文档，但混入 fastapi-cloud 等无关来源 |
| tut-14 | 40% | 2/5 | 「如何测试应用」召回了测试以外的配置类 chunk |
| tut-20 | 40%（外部 67%） | 2/5 | 流式响应题召回了大量异步/生命周期内容 |
| dep-03 | 80% | 4/5 | 基本正确，1 条噪声 |
| how-01 | 75% | 3/4 | GraphQL 相关，1 条噪声 |

共性原因：**BM25 对「如何 / 使用 / 怎么 / 应用」这类泛词权重过高**，且 chunk 以整篇文档为单位时，同一文档内不相关小节会整块进入上下文。由于 top_k=5 且 `min_sources=2`，系统倾向凑满 5 条，噪声被放大。

## 4. 生成层分析

### 4.1 长度与完整度

| 统计量 | 本地 | 外部 | 比值 |
|---|---|---|---|
| 平均字数 | 575 | 1020 | 1.77× |
| 中位数字数 | 505 | 1030 | 2.04× |
| 最小 / 最大 | 122 / 1755 | 441 / 1515 | — |
| 答案覆盖度 | 87.0% | 94.4% | +7.4pt |
| 平均耗时 | 23.9s | 5.0s | 4.8× |

- 本地模型存在明显的「短答」与「重复」两极：tut-01 只有 122 字（答案覆盖仍 100%），tut-20 生成 1755 字（含大段复述资料），tut-04 出现同句重复 30+ 次导致 57.9s。
- 外部模型长度分布集中在 600~1500 字，没有退化重复，单题耗时稳定在 2.9~6.3s。

### 4.2 忠实度：均值接近，分布完全不同

| 分布特征 | 本地 | 外部 |
|---|---|---|
| 词面忠实度均值 | 78.8% | 78.0% |
| 估计标准差 | 约 25pt | 约 12pt |
| 100% 的题数 | 13/36 | 3/36 |
| ≤50% 的题数 | 6/36 | 1/36 |

- 本地是**双峰分布**：要么大段复述资料（词面 100%），要么整段自由发挥（0~40%）。外部是**单峰**，稳定在 70~95%。
- 这说明词面指标对「改写型」回答天然低估：外部模型答案更长、更多同义替换，词面覆盖被稀释，但语义 judge 反而更高（87.8%）。**同一份回答在词面指标上被判低，不等于不忠实。**
- 反过来，tut-18 是真正的无支撑案例：本地词面 0%、本地 judge 0%、外部 judge 0%，三方一致，属于模型脱离资料自由作答。

### 4.3 外部 judge 的自评偏差

- 同一批本地答案：本地 judge 81.0% vs 外部 judge 58.7%，差 **22.3pt**——1.5B 判定模型明显更宽松（且存在自我偏好）。
- 外部答案由 DeepSeek 自己判定得 87.8%，比它判本地答案高 29.1pt，其中既包含真实的质量提升，也包含风格/长度偏好与自评偏差，**不可直接当作「质量提升 29pt」引用**。
- 可信的跨模型对比只看独立指标：引用正确率（90.4% vs 89.3%，无显著差异）、答案覆盖（94.4% vs 87.0%）、耗时（5.0s vs 23.9s）。

## 5. 指标之间的矛盾与解释

| 表面矛盾 | 解释 | 结论 |
|---|---|---|
| 引用正确率 90.4%，但外部 judge 只有 58.7%（本地答案） | 前者只验证「来源是否相关」，后者验证「答案句子是否有资料支撑」；模型会从正确来源里补写资料没有的代码与参数 | 引用正确 ≠ 忠实，两个指标必须并列报告 |
| 词面忠实 78.0%，但外部 judge 87.8% | 词面指标惩罚同义改写；judge 允许语义等价 | 词面指标适合回归对比，不适合对外宣称 |
| 答案覆盖 94.4%，但 how-04 引用 0% | 模型用通用知识答对了部分内容，但没有引用到目标文档 | 覆盖度可被「常识」虚高，需与引用指标联合看 |
| 精排后 Hit@4 下降、MRR 上升 | 二值指标 vs 排序指标对同一改动的敏感方向不同 | 检索评测应以 MRR 为主、Hit@k 为辅 |

## 6. 错误模式分类

| 类型 | 典型题目 | 证据 | 影响面 |
|---|---|---|---|
| A. 语料缺代码（占位符） | tut-04、adv-01、adv-03、adv-07、dep-02 | 语料中代码为 `{* docs_src/... *}`；补写的代码在上下文里找不到对应文本 | 外部 judge 低分的主要来源，约 8~10 条 |
| B. 文档本身是空壳 | how-04 | `testing-database.md` 仅 3 行外链，无正文 | 1 条，引用 0%、答案覆盖 0~50% |
| C. 小模型退化 | tut-04、tut-20 | 同句重复 30+ 次；大段复述资料 | 仅本地，1~2 条，显著拉高延迟 |
| D. 检索噪声 | dep-01、tut-14、tut-20、dep-03、how-01 | 5 条来源中 1~2 条相关；BM25 泛词 + chunk 粒度粗 | 5 条，拉低引用正确率 |
| E. 问题词表与答案口径不一致 | adv-03 | 旧版 answer_keywords 要求「WebSockets 客户端 / WebSocket 连接」，答案只讲安装与创建 | 已通过提示词修复覆盖度，但 judge 仍低（缺代码） |
| F. 评测实现截断 | 长上下文题目 | judge 的 context 截断 3000 字符 | 可能低估 3~5 条的真实忠实度 |

> 注：A/C/E 已在具体样本上人工核对；D/F 为基于指标分布与实现代码的推断，需抽样复核。

## 7. 统计不确定性（重要）

36 条样本下，**1 条 = 2.78pt**，统计噪声远大于很多人以为的「±2pt」：

| 指标 | 本地（均值 ± 95% CI） | 外部（均值 ± 95% CI） | 差异是否显著 |
|---|---|---|---|
| 引用正确率 | 89.3 ± 8.1 | 90.4 ± 7.4 | 否（区间大面积重叠） |
| 答案覆盖度 | 87.0 ± 7.9 | 94.4 ± 5.1 | 边缘（倾向外部更高） |
| 词面忠实度 | 78.8 ± 8.2 | 78.0 ± 4.0 | 否 |
| 检索 MRR | 0.9537（确定性计算，无采样噪声） | 同左 | 对比 0.8843 可信 |

结论：
- 「本地 vs 外部 引用正确率 +1.1pt」「词面忠实 −0.8pt」都应读作**没有差异**。
- 「答案覆盖 +7.4pt」是当前唯一值得写进结论的生成侧差异，但仍建议在论文中标注样本量与置信区间。
- temperature=0.7 会带来约 ±3~5pt 的重复实验波动，与上述区间叠加后，**小于 8pt 的差异都不应作为结论**。

## 8. 效度威胁

| 类型 | 威胁 | 缓解 |
|---|---|---|
| 构造效度 | 引用正确率是关键词命中，不等于语义相关；答案覆盖可被常识命中 | 与 LLM judge 并列报告；补充人工抽检 10~15 条 |
| 构造效度 | 词面忠实偏向逐字复述，系统性低估改写型模型 | 明确其为回归指标，不作对外主指标 |
| 内部效度 | judge 上下文截断 3000 字符 | 按来源顺序截断或分块判定后加权 |
| 内部效度 | 外部 judge 自评（生成=判定同模型） | 换第三方模型（qwen-plus / gpt-4o-mini）复核 |
| 外部效度 | 36 条题面取自文档标题，比真实用户提问更「好检」 | 扩充到 100+ 条，加入口语化、追问、否定式问题 |
| 外部效度 | 单一领域、单一语言、官方文档结构规整 | 增加 1 个异构语料（如项目 README / Issue）做迁移测试 |
| 性能效度 | 端到端仅 3 条采样（12.46s），与答案评测均值 23.9s 不一致 | 统一到 36 条全量，报告 P50/P95 |

> 关于 12.46s 与 23.9s 的差异：benchmark 的 3 条是短问题，答案评测包含 tut-20（1755 字）、tut-04（57.9s）等长尾，均值被拉高。两者口径不同，不能互相替代。

## 9. 改进优先级

| 优先级 | 动作 | 预期收益 | 成本 | 依据 |
|---|---|---|---|---|
| P0 | 把 `docs_src` 代码真实内容导入语料（替换 `{* ... *}` 占位符） | 外部 judge +10~15pt；代码类问题可被支撑 | 中（重新分块 + 向量化 + 重跑 36 条） | 错误模式 A，8~10 条受影响 |
| P0 | judge 改用独立第三方模型，避免自评 | 消除 ~29pt 的自评偏差，指标可对外 | 低（只加 `--judge-model`） | 4.3 节 |
| P1 | 本地生成加 `no_repeat_ngram_size` / `repetition_penalty`，或降到 temp 0.3 | 消除 tut-04 类退化，延迟 −30s（长尾） | 低 | 错误模式 C |
| P1 | BM25 停用词（如何/使用/怎么/什么/应用）+ 按 section 聚合、同文档去重 | 引用正确率 +3~5pt（dep-01/tut-14/tut-20） | 中 | 3.2 节 |
| P1 | judge 按来源分块判定再汇总，避免 3000 字符截断 | 忠实度估计更准（预计 +2~4pt） | 低 | 错误模式 F |
| P2 | 精排降延迟：max_length 128 + batch 16，或换 small 精排 | 检索 1.76s → 0.8s 量级 | 低~中 | 3.1 节 |
| P2 | 评测集扩到 100+ 条，报告置信区间 | 结论可信度提升 | 中 | 第 7 节 |
| P2 | 端到端性能统一 36 条全量 | 延迟数据可写进论文 | 低 | 第 8 节 |

**天花板判断**：在现有语料与 1.5B 生成器下，引用正确率约 92~94% 见顶（剩余噪声来自 dep-01/how-04），答案覆盖约 95%；外部 judge 在补齐代码前难以超过 65~70%。若完成 P0 的语料补齐，外部 judge 有望进入 75~80% 区间。

---

## 10. 结论

1. **检索链路已达到可交付水平**：Hit@4 97.2%、MRR 0.9537，精排是确定性收益，剩余失败集中在语料空壳文档。
2. **生成链路的核心矛盾是「完整度 vs 可验证性」**：外部模型把答案覆盖推到 94.4%、耗时降到 5.0s，但语料缺代码导致补写内容无法被 judge 支撑；本地模型虽有复述优势，但存在重复退化与长尾延迟。
3. **指标的可靠性需要分层表述**：检索指标（Hit/MRR）可直接作为结论；引用正确率需标注关键词启发式；词面忠实度只作回归；LLM judge 必须注明判定模型，跨模型/自评场景不可直接比较。
4. **下一步应优先补语料、换独立 judge**，而不是继续调 top_k / 阈值——四组阈值实验已经证明这些参数在当前语料上的收益在噪声以内。
